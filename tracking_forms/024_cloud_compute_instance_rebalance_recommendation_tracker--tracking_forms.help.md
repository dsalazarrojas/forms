# Cloud Compute Instance Rebalance Recommendation Tracker - Help Guide
## Purpose

The form is used to track recommendations for rebalancing cloud compute instances to optimize resource usage and costs.

## How To Complete This Form

1. Select the recommendation ID and submission date to identify the recommendation.
2. Enter the instance ID, provider, region, current CPU and memory utilization, and recommended action for the instance.
3. Choose the recommended action (e.g., downsize, upsize, change instance type, auto-scale, consolidate instances).
4. If applicable, specify the recommended instance type.
5. Estimate the monthly savings and expected performance impact.
6. Assign the recommendation to a person, department, and email address.
7. Set the current status and target implementation date.
8. Add any notes or additional details.

## Field-by-Field Explanation

* **Recommendation ID - Reference Number**: Enter the unique identifier for this recommendation.
* **Submission Date**: Enter the date when this recommendation was identified.
* **Submitted By - Name**: Enter the person who identified this recommendation.
* **Instance ID - Name**: Enter the identifier for the cloud instance in question.
* **Current Instance Type**: Enter the current type of the cloud instance (e.g., t3.large, m5.xlarge).
* **Cloud Provider**: Choose the cloud provider (e.g., AWS, Microsoft Azure, Google Cloud).
* **Region - Location**: Enter the region where the instance is located.
* **Current CPU Utilization - Percentage**: Enter the average CPU utilization over a recent period.
* **Current Memory Utilization - Percentage**: Enter the average memory utilization over a recent period.
* **Recommended Action**: Choose the recommended action (e.g., downsize, upsize, change instance type, auto-scale, consolidate instances).
* **Recommended Instance Type**: If applicable, enter the recommended instance type.
* **Estimated Monthly Savings - USD**: Estimate the potential monthly savings.
* **Expected Performance Impact**: Choose the expected performance impact (e.g., improvement, no impact, potential degradation, unknown).
* **Assigned To - Name**: Enter the person responsible for taking the action.
* **Department - Team**: Enter the department or team responsible for the action.
* **Assigned Person Email**: Enter the email address of the person responsible for the action.
* **Current Status**: Choose the current status (e.g., new, in review, approved, in progress, completed, rejected, on hold).
* **Target Implementation Date**: Set the target date for implementation.
* **Notes and Additional Details**: Add any context, blockers, or additional details.
