# Application Layer Protocol Information Request Form - Help Guide
## Purpose
This form is used to collect information about the application layer protocol requested by the user.

## How To Complete This Form
1. Fill in the general information about the request, including the request date and a unique ID for tracking.
2. Provide specific details about the protocol, such as its name, type, and version.
3. Specify the encryption method and authentication type used.
4. List any supported features and system requirements.
5. Indicate if documentation is available and its level of comprehensiveness.
6. Report the current testing status of the protocol.
7. Add any additional information or notes about the protocol.

## Field-by-Field Explanation

* **Request Date** (`request_date`, required): Enter the date when the request was made.
* **Request ID** (`request_id`, optional): Enter a unique ID for tracking purposes, if applicable.
* **Requestor Name** (`requestor_name`, required): Enter the name of the person or team making the request.
* **Requestor Email** (`requestor_email`, required): Enter the email address of the person or team making the request.
* **Department or Team** (`department`, optional): Enter the department or team responsible for the request.
* **Protocol Name** (`protocol_name`, required): Enter the name of the protocol being requested.
* **Protocol Type** (`protocol_type`, required): Select the type of protocol being requested (e.g., HTTP/HTTPS, SMTP, FTP/SFTP, SSH, MQTT, CoAP, DNS, SNMP, Custom).
* **Protocol Version** (`protocol_version`, optional): Enter the version of the protocol being requested.
* **Port Number** (`port_number`, optional): Enter the port number used by the protocol.
* **Protocol Description and Purpose** (`protocol_description`, required): Provide a brief description and purpose of the protocol.
* **Implementation Details** (`implementation_details`, optional): Enter any additional information about the implementation of the protocol.
* **Supported Features** (`supported_features`, optional): Select all supported features (e.g., Encryption, Authentication, Compression, Error handling, Load balancing, Caching).
* **Encryption Method** (`encryption_method`, optional): Select the encryption method used (e.g., AES, RSA, TLS, SSL, None, Other).
* **Authentication Type** (`authentication_type`, optional): Select the authentication type used (e.g., Basic auth, Token-based, OAuth, Certificate, API key, None).
* **System Requirements** (`system_requirements`, optional): Enter the minimal resources and dependencies needed to support the protocol.
* **Is documentation available?** (`documentation_provided`, optional): Select whether documentation is available and its level of comprehensiveness (e.g., Yes, comprehensive, Yes, basic, Limited, No documentation).
* **Testing Status** (`testing_status`, optional): Select the current testing status of the protocol (e.g., In development, Testing phase, Pilot deployment, Production).
* **Additional Information or Notes** (`additional_information`, optional): Enter any additional information or notes about the protocol.
