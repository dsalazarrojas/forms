# 2D System Log Submission - Help Guide
## Purpose
The 2D System Log Submission form is used to document and record events, issues, and incidents related to the system's operation. This form is intended to provide a standardized way of reporting and tracking system events, enabling swift identification, analysis, and resolution of problems. It captures essential details about the event, including the system's status, error code, and impact on business operations.

## How To Complete This Form
To submit an event, follow these steps:

1. Click on the "2D System Log Submission" button to open the form.
2. Enter the name of the person documenting the event (Inspector/Auditor name) in the "Inspector/Auditor name" field.
3. Select the "Date of log entry" and "Time of log entry" fields to record the exact time of the event.
4. Enter the unique system ID or identifier in the "System ID or identifier" field.
5. Provide the location or site of the system in the "Location or site of system" field.
6. Choose the type of event that occurred (e.g., Routine maintenance, Error occurrence, etc.) in the "Type of event logged" field.
7. Determine the severity level of the event (e.g., Critical, High, Medium, etc.) in the "Severity level" field.
8. Select the current system status in the "Current system status" field.
9. List all affected system components (e.g., Database, Network, etc.) in the "Affected system components" field.
10. If applicable, enter the system-generated error code or reference number in the "Error code or reference number" field.
11. Record the duration of the event in minutes in the "Duration of event (minutes)" field.
12. Estimate the approximate number of users impacted by the event in the "Number of impacted users" field.
13. Assess the business impact of the event (e.g., No impact, Minimal impact, Moderate impact, etc.) in the "Business impact assessment" field.
14. Specify how the event was detected (e.g., Automated monitoring, User report, etc.) in the "How was this event detected?" field.
15. Choose the resolution status of the event (e.g., Resolved, In progress, etc.) in the "Resolution status" field.
16. Record the time it took to resolve the issue in hours in the "Time to resolution (hours)" field.
17. Select the root cause category of the event (e.g., Human error, Hardware failure, etc.) in the "Root cause category" field.
18. Suggest preventive measures to prevent similar events in the future in the "Recommended preventive measures" field.
19. Provide any additional comments or notes about the event in the "Additional comments or notes" field.
20. Determine if the event requires escalation in the "Does this require escalation?" field.
21. Specify the next review date for the event in the "Next review date" field.

## Field-by-Field Explanation

* **Inspector/Auditor name** (2): Enter the name of the person documenting this event.
* **Date of log entry** (3): Select the exact date of the event.
* **Time of log entry** (4): Select the exact time of the event.
* **System ID or identifier** (5): Enter the unique identifier for the system being logged.
* **Location or site of system** (6): Provide the physical location of the system.
* **Type of event logged** (7): Choose the type of event that occurred (e.g., Routine maintenance, Error occurrence, etc.).
* **Severity level** (8): Determine the severity level of the event (e.g., Critical, High, Medium, etc.).
* **Current system status** (9): Select the current system status (e.g., Operational, Down, etc.).
* **Affected system components** (10): List all affected system components (e.g., Database, Network, etc.).
* **Error code or reference number** (11): If applicable, enter the system-generated error code or reference number.
* **Duration of event (minutes)** (12): Record the duration of the event in minutes.
* **Number of impacted users** (13): Estimate the approximate number of users impacted by the event.
* **Business impact assessment** (14): Assess the business impact of the event (e.g., No impact, Minimal impact, Moderate impact, etc.).
* **How was this event detected?** (15): Specify how the event was detected (e.g., Automated monitoring, User report, etc.).
* **Resolution status** (16): Choose the resolution status of the event (e.g., Resolved, In progress, etc.).
* **Time to resolution (hours)** (17): Record the time it took to resolve the issue in hours.
* **Root cause category** (18): Select the root cause category of the event (e.g., Human error, Hardware failure, etc.).
* **Recommended preventive measures** (19): Suggest actions to prevent similar events in the future.
* **Additional comments or notes** (20): Provide any additional comments or notes about the event.
* **Does this require escalation?** (21): Determine if the event requires escalation.
* **Next review date** (22): Specify the next review date for the event.
