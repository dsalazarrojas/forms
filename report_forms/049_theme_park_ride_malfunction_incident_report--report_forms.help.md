# Theme Park Ride Malfunction Incident Report - Help Guide
## Purpose
This form is used to report malfunctions on theme park rides, providing essential information for the theme park to respond and resolve the issue.

## How To Complete This Form
To complete this form, follow these steps:

1.  Select the incident date from the calendar.
2.  Enter the name of the ride involved in the malfunction.
3.  Provide a detailed description of the malfunction.
4.  Choose the type of incident (e.g., maintenance, equipment failure, rider error, or other).
5.  If applicable, add follow-up details, witness names and statements, and follow-up actions and notes.
6.  Select the team and technician assigned to the incident.
7.  Mark the incident as open, closed, or in progress.

## Field-by-Field Explanation

*   **Incident Date** (`incident_date`, date, `required`): Enter the date the malfunction occurred. This is a required field to track the timeline of incidents.
*   **Ride Name** (`ride_name`, text, `required`): Provide the name of the ride involved in the malfunction.
*   **Malfunction Description** (`malfunc_description`, text, `required`): Describe the specific issue that occurred on the ride.
*   **Incident Type** (`incident_type`, select_one, `required`): Choose the type of incident from the provided options (maintenance, equipment failure, rider error, or other).
*   **Follow-up Details** (`followup_details`, text, `optional`): If relevant, add any additional information about follow-up actions or discussions.
*   **Witness Names** (`witness_names`, text, `optional`): List any witnesses who may have seen the malfunction.
*   **Witness Statements** (`witness_statements`, text, `optional`): Record the statements or observations of the witnesses.
*   **Follow-up Actions** (`followup_actions`, text, `optional`): Describe any follow-up actions taken by the theme park or technician.
*   **Follow-up Notes** (`followup_notes`, text, `optional`): Add any additional notes from follow-up discussions or actions.
*   **Assigned Team** (`assigned_team`, text, `required`): Select the team assigned to investigate or resolve the incident.
*   **Assigned Technician** (`assigned_technician`, text, `required`): Choose the technician assigned to address the issue.
*   **Incident Status** (`incident_status`, select_one, `required`): Mark the incident as open, closed, or in progress.

## Tips

*   Please ensure that you're reporting only new incidents and not revisiting previously reported issues.
*   If you're unsure about the incident type, choose the "other" option and provide a brief description in the malfunction description field.
*   Keep the witness statements and follow-up notes concise and clear for easier reference and analysis.
