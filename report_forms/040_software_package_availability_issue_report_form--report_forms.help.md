# software_package_availability_issue_report_form - Help Guide
## Purpose
This form is designed to collect information about software package availability issues, allowing IT teams or support staff to track and resolve these problems efficiently.

## How To Complete This Form
To complete this form, follow these steps:
1. Select the "Issue Type" from the provided options (Availability Issue, Access Issue, or Maintenance Issue).
2. Provide a detailed description of the issue in the "Issue Description" field.
3. Choose the priority level (High, Medium, or Low) that best represents the severity of the issue.
4. Specify the affected software version and environment.
5. Identify the affected user.
6. Enter the date the issue was reported.
7. Add any comments about the issue.
8. Select the status of the issue (Assigned, In Progress, Resolved, or Closed).
9. Choose the team members assigned to the issue.
10. Set a due date for the resolution.
11. If applicable, enter the date the issue was resolved and by whom.
12. Set a closed date for the issue.
13. Provide a resolution to the issue.
14. Add any additional comments.
15. If relevant, enter any related tickets.
16. Select the software packages affected by the issue.
17. Enter the priority level and time spent to resolve the issue.
17. Identify the submitter.

## Field-by-Field Explanation
* **Software Package** (`software_package`, text, optional): Enter the name or description of the software package experiencing the issue.
* **Issue Type** (`issue_type`, select_one, required): Choose the type of issue (Availability Issue, Access Issue, or Maintenance Issue).
* **Issue Description** (`issue_description`, text, optional): Provide a detailed description of the issue.
* **Priority** (`priority`, select_one, required): Select the priority level (High, Medium, or Low) that best represents the severity of the issue.
* **Affected Software Version** (`affected_software_version`, text, optional): Enter the affected software version.
* **Affected Software Environment** (`affected_software_environment`, text, optional): Enter the affected software environment.
* **Affected User** (`affected_user`, text, optional): Identify the affected user.
* **Report Date** (`report_date`, date, optional): Enter the date the issue was reported.
* **Comments** (`comments`, text, optional): Add any additional comments about the issue.

* **Resolved Date** (`resolved_date`, date, optional): If applicable, enter the date the issue was resolved.
* **Closed Date** (`closed_date`, date, required): Set a closed date for the issue.
* **Resolution** (`resolution`, text, optional): Provide a resolution to the issue.
