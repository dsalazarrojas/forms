# Game Level Design Checklist - Help Guide
## Purpose
This form is designed to help game developers and designers evaluate and document the quality of a game level. It covers various aspects of level design, including gameplay, visual, and technical considerations.

## How To Complete This Form
To complete this form, follow these steps:

1. Select the relevant level design categories that apply to your evaluation:
	* Choose the level design categories from the first dropdown menu "Level Design".
2. Evaluate the level's design based on the selected categories:
	* For each selected category, choose "High", "Low" or "Yes/No" from the respective dropdown menu.
3. If you need to provide additional details about the level design, use the "Game Level Description" field.
4. Complete the form by selecting "Submit".

## Field-by-Field Explanation
### Level Design
**Level Design** (`level_design`, Select Multiple)
Select the level design categories that apply to your evaluation. Choose "High" if the level's design meets the expected standards, "Low" if it falls short of expectations.

### Gameplay Evaluation
**Gameplay Evaluation** (`gameplay_evaluation`, Select One)
Indicate whether the gameplay experience in this level is satisfactory ("Yes") or not ("No").

### Game Visuals
**Game Visuals** (`game_visuals`, Select One)
Evaluate the level's visual presentation and choose "Yes" if it meets the expected standards and "No" otherwise.

### Technical Issues
**Technical Issues** (`technical_issues`, Select Multiple)
Select any technical issues that affect the level's performance or stability.

### Player Guidance
**Player Guidance** (`player_guidance`, Select Multiple)
Evaluate whether the level provides sufficient guidance for the player to navigate through it, choosing "Yes" if it does and "No" otherwise.

### Level Testing
**Level Testing** (`level_testing`, Select One)
Choose "High" if the level has been thoroughly tested and meets the expected standards, "Low" if it has not been adequately tested.

### Game Level Description
**Game Level Description** (`game_level_description`, Text)
Provide a brief description of the level, including any notable features or mechanics.

### Gameplay Balance
**Gameplay Balance** (`gameplay_balance`, Select One)
Evaluate whether the level's difficulty and reward structure are balanced, choosing "Yes" if it is and "No" otherwise.
