# Cloud Compute Instance Rebalance Recommendation Tracker - Help Guide
## Purpose
The Cloud Compute Instance Rebalance Recommendation Tracker is a tool used to track and manage recommendations for rebalancing cloud compute instances. It helps users to identify areas where instance sizes can be adjusted to optimize costs, performance, and utilization. This form is intended to guide users through the process of submitting and tracking rebalance requests for cloud instances.

## How To Complete This Form
To complete this form, follow these steps:

1. Enter a Unique Recommendation ID in the "Recommendation ID" field.
2. Select the date when the recommendation was generated in the "Submission Date" field.
3. Provide the name of the compute instance being rebalanced in the "Instance Name or Identifier" field.
4. Describe the current configuration and size of the instance in the "Current Instance Type" field.
5. Enter the recommended new configuration in the "Recommended Instance Type" field.
6. Enter the current monthly cost of the instance in the "Current Monthly Cost" field.
7. Project the estimated monthly savings with the rebalance in the "Estimated Monthly Savings" field.
8. Select the reason for rebalancing from the options provided in the "Reason for Rebalance" field.
9. Identify the type of application running on the instance in the "Type of Application" field.
10. Provide the name and email address of the instance owner or team lead in the "Instance Owner or Team Lead" and "Owner Email Address" fields.
11. Select the current status of the recommendation in the "Decision Status" field.
12. If applicable, enter the date when the decision to rebalance was made in the "Decision Date" field.
13. If applicable, enter the planned implementation date for the rebalance in the "Planned Implementation Date" field.
14. Assess the risk level associated with the rebalance in the "Risk Assessment" field.
15. If applicable, select the amount of downtime required for implementation in the "Downtime Required for Implementation" field.
16. Enter any additional notes or concerns related to the rebalance in the "Additional Notes or Concerns" field.

## Field-by-Field Explanation
### 1. Recommendation ID (`recommendation_id`)
*   Unique identifier for tracking
### 2. Submission Date (`submission_date`)
*   Date the recommendation was generated
### 3. Instance Name or Identifier (`instance_name`)
*   Name of the compute instance being rebalanced
### 4. Current Instance Type (`current_instance_type`)
*   Current configuration and size of the instance
### 5. Recommended Instance Type (`recommended_instance_type`)
*   Suggested new configuration
### 6. Current Monthly Cost (`current_monthly_cost`)
*   Current monthly cost of the instance
### 7. Estimated Monthly Savings (`estimated_monthly_savings`)
*   Projected cost reduction with the rebalance
### 8. Reason for Rebalance (`utilization_reason`)
*   Why this recommendation was made (e.g., CPU Underutilization, Memory Underutilization, etc.)
### 9. Type of Application (`workload_type`)
*   Type of application running on the instance (e.g., Web Server, Database, etc.)
### 10. Instance Owner or Team Lead (`owner_name`)
*   Name of the instance owner or team lead
### 11. Owner Email Address (`owner_email`)
*   Email address of the instance owner or team lead
### 12. Decision Status (`decision_status`)
*   Current status of the recommendation (e.g., Pending Review, Approved, etc.)
### 13. Decision Date (`decision_date`)
*   Date the decision to rebalance was made
### 14. Planned Implementation Date (`implementation_planned`)
*   Target date for implementing the rebalance
### 15. Risk Assessment (`risk_assessment`)
*   Potential risks associated with the rebalance (e.g., Low Risk, Medium Risk, High Risk)
### 16. Downtime Required for Implementation (`downtime_required`)
*   Amount of downtime required for implementation (e.g., No Downtime, Minutes, Hours, etc.)
### 17. Additional Notes or Concerns (`additional_notes`)
*   Any relevant information or concerns related to the rebalance
