# Website Downtime Incident Form - Help Guide
## Purpose
This form is used to report a website downtime incident. It helps to track and document the incident, including its start and end times, affected users, resolution status, and other relevant details.

## How To Complete This Form
To complete this form, please follow the instructions below:

* Fill in the required fields (marked as "required" in the form).
* Select the relevant options for each field, such as the website downtime type, incident status, and resolution status.
* Provide a clear and concise description of the incident.
* Make sure to include all necessary information to ensure accurate tracking and resolution of the incident.

## Field-by-Field Explanation
* **Website Downtime Start Time (1)** (`date`): Enter the date and time when the website downtime started.
* **Website Downtime End Time (2)** (`date`): Enter the date and time when the website downtime ended.
* **Website Downtime Duration (3)** (`number`): Enter the duration of the website downtime in hours and minutes.
* **Website Error Message (4)** (`text`): Enter a brief error message related to the website downtime.
* **Affected Users (5)** (`select_multiple`): Select all affected users (e.g. employees, customers, etc.).
* **Assigned Team Member (6)** (`select_one`): Select the team member assigned to resolve the incident.
* **Resolution Status (7)** (`select_one`): Select the resolution status (e.g. resolved, in progress, etc.).
* **Comments (8)** (`text`): Provide any additional comments or notes related to the incident.
* **Error Message (9)** (`text`): Enter any error messages related to the incident.
* **Website Downtime Impact (10)** (`select_one`): Select the impact of the website downtime (e.g. low, medium, high).
* **Incident Description (11)** (`text`): Provide a brief description of the incident.
* **Resolution Notes (12)** (`text`): Enter any resolution notes related to the incident.
* **Resolved By (13)** (`select_one`): Select the person who resolved the incident.
* **Resolved Time (14)** (`date`): Enter the date and time when the incident was resolved.
* **Resolved Date (15)** (`date`): Enter the date when the incident was resolved.
* **Website Downtime Cause (16)** (`select_multiple`): Select all causes of the website downtime.
* **Comments (17)** (`text`): Provide any additional comments or notes related to the incident.
* **Incident Number (18)** (`text`): Enter the incident number (if available).
* **Website URL (19)** (`text`): Enter the website URL affected by the downtime.
* **Website Downtime Type (20)** (`select_one`): Select the type of website downtime (e.g. planned, unplanned, etc.).
* **Error Messages (21)** (`text`): Enter any error messages related to the incident.
* **Website Downtime Duration (22)** (`number`): Enter the duration of the website downtime in hours and minutes.
* **Duration (23)** (`number`): Enter the duration of the incident.
* **Incident Status (24)** (`select_one`): Select the status of the incident (e.g. open, resolved, etc.).
* **Assigned Tool (25)** (`text`): Enter the tool assigned to resolve the incident (if any).
