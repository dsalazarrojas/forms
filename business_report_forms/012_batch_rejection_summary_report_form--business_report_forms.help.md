# Batch Rejection Summary Report Form - Help Guide

## Purpose
This form is used to document the rejection of a batch of products, including the reasons for rejection, the corrective actions taken, and the expected outcomes. It is an essential tool for the quality control team to track and analyze product issues to prevent future occurrences.

## How To Complete This Form

1. Enter the unique **Report ID** (required) to identify the report.
2. Enter the **Report Date**, which is the date the report was created (required).
3. Provide the **Batch ID** (required), which is the unique identifier for the rejected batch.
4. Enter the **Product Name** (required), which is the name of the product being rejected.
5. Enter the **Production Date** (required), which is the date the batch was produced.
6. Enter the **Rejection Date** (required), which is the date the batch was rejected.
7. Enter the **Total Batch Quantity** (required), which is the number of units in the batch.
8. Enter the **Rejected Quantity** (required), which is the number of units rejected.
9. Select the **Rejection Category** (required), which is the primary reason for rejection (e.g., Quality Defect, Specification Deviation, etc.).
10. Select the **Defect Type** (optional), which is a specific defect identified.
11. Enter the **Root Cause** (required), which is what caused the rejection.
12. Enter the **Discovered By** (required), which is the name of the person who found the issue.
13. Select the **Discovery Stage** (required), which is when the issue was found (e.g., Incoming Inspection, In-Process Inspection, etc.).
14. Enter the **Estimated Financial Impact** (optional), which is the cost of rejection.
15. Select the **Batch Disposition** (required), which is the action to be taken on the batch (e.g., Scrap, Reword, etc.).
16. Enter the **Corrective Action Plan** (required), which is the steps to prevent future occurrences.
17. Enter the **Responsible Party** (required), which is the name of the person implementing the corrective action.
18. Enter the **Target Completion Date** (required), which is when the corrective action will be completed.
19. Enter the **Name of Person Creating Report**, **Reported By** (required), which is the name of the person creating the report.
20. Enter any **Additional Notes** (optional), which are any other relevant details.

## Field-by-Field Explanation

* **Report ID**: Unique report identifier.
* **Report Date**: Date the report was created.
* **Batch ID**: Unique batch identifier.
* **Product Name**: Name of the product being rejected.
* **Production Date**: Date the batch was produced.
* **Rejection Date**: Date the batch was rejected.
* **Total Batch Quantity**: Number of units in the batch.
* **Rejected Quantity**: Number of units rejected.
* **Rejection Category**: Primary reason for rejection.
* **Defect Type**: Specific defect identified.
* **Root Cause**: What caused the rejection.
* **Discovered By**: Name of person who found the issue.
* **Discovery Stage**: When the issue was found.
* **Estimated Financial Impact**: Cost of rejection (if available).
* **Batch Disposition**: Action to be taken on the batch.
* **Corrective Action Plan**: Steps to prevent recurrence.
* **Responsible Party**: Name of person implementing corrective action.
* **Target Completion Date**: When corrective action will be completed.
* **Reported By**: Name of person creating report.
* **Additional Notes**: Any other relevant information.
