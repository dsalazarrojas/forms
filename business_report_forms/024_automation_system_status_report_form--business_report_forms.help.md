# Automation System Status Report Form - Help Guide

## Purpose
The Automation System Status Report Form is used to report on the status of an automation system, including its overall status, performance, and any incidents or issues that have occurred. This form is essential for monitoring and maintaining the system's health and performance.

## How To Complete This Form

1. Fill out the form with the required information for each field.
2. Make sure to select the correct reporting period (Daily, Weekly, Monthly, Quarterly, or Annual).
3. Enter accurate numbers for the performance metrics (Average Response Time, Peak Load Time, Average CPU Usage, Average Memory Usage, and Error Rate).
4. Enter the number of incidents reported and critical incidents.
5. Briefly describe any incidents or issues in the Incident Summary field.
6. If necessary, provide maintenance performed and planned maintenance information.

## Field-by-Field Explanation

* **Report Date** (`report_date`, required): This is the date when the report is submitted. Select the correct date using the provided date picker.
* **Reporting Period** (`report_period`, required): Choose the reporting period (Daily, Weekly, Monthly, Quarterly, or Annual) that matches the report's scope.
* **Reporting Team** (`reporting_team`, required): Enter the name of the team responsible for reporting the system status.
* **Automation System Name** (`system_name`, required): Enter the name of the automation system being reported on.
* **System Version** (`system_version`, optional): Enter the current version of the automation system (if applicable).
* **Environment** (`system_environment`, required): Select the environment where the system is running (Production, Staging, Development, or Testing).
* **Overall System Status** (`overall_status`, required): Choose the overall status of the system (Operational, Degraded, Warning, Critical, or Maintenance).
* **Uptime Percentage** (`uptime_percentage`, required): Enter the percentage of time the system has been running without errors.
* **Available Hours** (`availability_hours`, optional): Enter the total hours the system has been available.
* **Average Response Time** (`average_response_time`, required): Enter the average response time in milliseconds.
* **Peak Load Time** (`peak_load_time`, optional): Enter the peak load time in milliseconds.
* **Average CPU Usage** (`cpu_usage`, required): Enter the average CPU usage as a percentage.
* **Average Memory Usage** (`memory_usage`, required): Enter the average memory usage as a percentage.
* **Error Rate** (`error_rate`, required): Enter the error rate as a percentage.
* **Number of Incidents Reported** (`incidents_reported`, required): Enter the total number of incidents reported.
* **Critical Incidents** (`critical_incidents`, required): Enter the number of critical incidents.
* **Incident Summary** (`incident_summary`, optional): Briefly describe any incidents or issues.
* **Maintenance Performed This Period** (`maintenance_performed`, optional): If applicable, enter any maintenance performed during this period.
* **Planned Maintenance for Next Period** (`planned_maintenance`, optional): If applicable, enter any planned maintenance for the next period.

## Tips
* Make sure to fill out all required fields.
* Double-check the accuracy of the performance metrics and incidents reported.
* If you're unsure about any field, consult the system administrator or documentation.
