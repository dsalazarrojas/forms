# Browsing Restrictions Configuration Form - Help Guide
## Purpose
This form is used to submit a browsing restrictions configuration change request. It captures essential details required for the change to be implemented by the IT department.

## How To Complete This Form
To complete this form, follow these steps:

1.  Enter the requester's name.
2.  Provide the requester's email for notification purposes.
3.  Identify the target user or group to apply the restrictions.
4.  Choose the type of browsing restriction requested.
5.  If necessary, specify the affected sites or categories to block or allow.
6.  Select the effective date for the change to take effect.
7.  Indicate the IT approval status for the configuration change.
8.  Add any implementation notes for the IT staff.

## Field-by-Field Explanation

*   **Requester name** (requester_name): Enter the name of the person requesting the restriction change.
*   **Requester email** (requester_email): Enter the email address to receive notifications about the restriction change.
*   **Target user or group** (target_user_or_group): Enter the username or group name to which the restriction applies.
*   **Restriction type** (restriction_type): Choose the type of restriction you want to apply. This could be blocking certain categories, allowing only specific sites, restricting by time of day, or limiting bandwidth.
*   **Affected sites or categories** (affected_sites_or_categories): If you selected a restriction type that requires this, enter the specific domains or categories to block or allow. This is optional.
*   **Effective date** (effective_date): Select the date when you want the change to take effect. If left empty, the change will take effect immediately.
*   **Approval status** (approval_status): Select the status of the approval for the configuration change. This could be Approved, Pending, or Denied.
*   **Change notes** (change_notes): Add any notes or explanations to help the IT staff implement the change.

**Tips:**

*   Make sure to provide accurate information to ensure the correct implementation of the restriction change.
*   If the restriction type requires it, provide specific domains or categories to apply the change.
*   If the effective date is left empty, the change will take effect immediately, so consider specifying a date for a scheduled change.
*   Ensure the approval status is accurate to reflect the current state of the change request.
