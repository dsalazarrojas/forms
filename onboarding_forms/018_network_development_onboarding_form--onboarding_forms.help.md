# Network Development Onboarding Form - Help Guide
## Purpose
The Network Development Onboarding Form is used to collect and document information about new network development projects being onboarded to the team's knowledge base.

## How To Complete This Form
To complete this form, follow these steps:

1. Ensure you have all the necessary information about the project before starting.
2. Fill out the Project Details page with the project's name, description, and any other relevant details.
3. Select the team members involved in the project, including the Project Lead and any other relevant team members.
4. Choose the onboarding date for the project.
5. Indicate the onboarding status of the project, which can be Active, Inactive, or Pending.
6. If necessary, enter the Project Manager's name and any additional onboarding comments or notes.

## Field-by-Field Explanation

* **Project Details** (`project_details`, text, optional): Enter a brief description of the project.
* **Team Members** (`team_members`, select_multiple, required): Select all team members involved in the project, including the Project Lead and Development Team members.
* **Onboarding Date** (`onboarding_date`, date, optional): Choose the date the project was onboarded.
* **Onboarding Status** (`onboarding_status`, select_one, required): Select the onboarding status of the project, which can be Active, Inactive, or Pending.
* **Project Manager** (`project_manager`, text, optional): Enter the name of the Project Manager, if applicable.
* **Onboarding Notes** (`onboarding_notes`, text, optional): Add any additional notes or comments about the onboarding process.
* **Onboarding Comments** (`onboarding_comments`, text, optional): Enter any additional comments or feedback about the project.

## Tips

* Be as detailed as possible when filling out the Project Details page.
* Make sure to select all relevant team members to ensure accurate representation of the project's team.
* If the onboarding status is Pending, be sure to provide an estimate of when the project is expected to be onboarded.
* If entering onboarding notes or comments, keep them concise and clear, but thorough enough to provide context.
* Review and revise your submissions carefully before finalizing, as they will not be editable after submission.
