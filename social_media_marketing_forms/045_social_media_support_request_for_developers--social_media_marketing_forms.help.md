# Social Media Support Request For Developers - Help Guide
## Purpose
This form is used to collect information from developers about social media support requests. It helps us track and manage these requests effectively.

## How To Complete This Form
1. Fill out the form accurately and completely.
2. Be honest when answering the questions about the request status.
3. Provide as much detail as possible in the text fields.

## Field-by-Field Explanation

* **Email** (`email`, email, optional): Your email address is required for contact purposes.
* **Name** (`name`, text, optional): Your name or the name of the person requesting support.
* **Issue Type** (`issue_type`, select_multiple, optional): Select all that apply:
	+ Yes: The issue is related to social media.
	+ No: The issue is not related to social media.
* **Description** (`description`, text, optional): Describe the issue you're facing.
* **Developer Info** (`developer_info`, text, optional): Provide any relevant developer information about the issue.
* **Expected Response Time** (`expected_response_time`, time, optional): Time by which you expect a response.
* **Social Media Channel** (`social_media_channel`, select_multiple, optional): Select all that apply:
	+ Yes: The issue is related to a social media channel.
	+ No: The issue is not related to a social media channel.
* **Support Level** (`support_level`, select_multiple, optional): Select all that apply:
	+ High: High priority issue.
	+ Low: Low priority issue.
* **Support Team** (`support_team`, select_multiple, optional): Select all that apply:
	+ Yes: You are a support team member.
	+ No: You are not a support team member.
* **Status** (`status`, select_multiple, optional): Select all that apply:
	+ Active: The issue is active and being worked on.
	+ Inactive: The issue is not active.
* **Resolution** (`resolution`, text, optional): Describe how the issue was resolved.
* **Resolution Time** (`resolution_time`, date, optional): Date and time when the issue was resolved.
* **Resolution Date** (`resolution_date`, date, optional): Date when the issue was resolved.
* **Resolution Note** (`resolution_note`, text, optional): Note about the resolution.
* **Follow Up** (`follow_up`, select_multiple, optional): Select all that apply:
	+ Yes: You want to follow up on the issue.
	+ No: You do not want to follow up on the issue.
* **Follow Up Time** (`follow_up_time`, time, optional): Time by which you want to follow up on the issue.
* **Follow Up Date** (`follow_up_date`, date, optional): Date by which you want to follow up on the issue.
* **Close Request** (`close_request`, select_multiple, optional): Select all that apply:
	+ Yes: You want to close the issue.
	+ No: You do not want to close the issue.
* **Close Request Time** (`close_request_time`, time, optional): Time by which you want to close the issue.
* **Close Request Date** (`close_request_date`, date, optional): Date by which you want to close the issue.
* **Close Request Note** (`close_request_note`, text, optional): Note about closing the issue.
* **Close Request Resolution** (`close_request_resolution`, text, optional): Description of the resolution of closing the issue.
* **Support Requester** (`support_requester`, text, optional): Name or description of the person requesting support.
* **Developer Comment** (`developer_comment`, text, optional): Any comment from the developer about the issue.
