# string_format_submission_form - Help Guide

## Purpose
This form is designed to collect technical submission information for developers, including submission titles, string formats, documentation requirements, and supporting teams.

## How To Complete This Form

1. Please provide the title of the submission in the "Title of the submission" field.
2. In the "Examples of string formats used" field, provide examples of string formats used in the submission.
3. If required, provide documentation requirements in the "Documentation requirements" field.
4. List the teams supporting the submission in the "Supporting teams" field.
5. If necessary, provide detailed specifications in the "Detailed specifications" field.
6. Provide the custom string format for the submission in the "String format" field.
7. If needed, provide additional information about the submission in the "Additional information" field.
8. You may also list the teams supporting the submission in the "Supporting teams 2" field, if applicable.
9. If required, list technical requirements for the submission in the "Technical requirements 2" field.
10. In the "Organizing requirements 2" field, list the requirements for organizing the submission.

## Field-by-Field Explanation

* **Title of the submission** (`Title of the submission`, `text`, required): This field requires the title of the submission, which should be a concise and descriptive name.
* **Examples of string formats used** (`Examples of string formats used`, `text`, optional): Provide examples of string formats used in the submission to give context to the reviewers.
* **Documentation requirements** (`Documentation requirements`, `text`, optional): If required, please provide documentation requirements for the submission.
* **Supporting developers** (`Supporting developers`, `text`, optional): List the developers supporting the submission to help with technical issues.
* **Organizing requirements** (`Organizing requirements`, `text`, optional): Provide organizing requirements for the submission to ensure it is easy to review.
* **Technical requirements** (`Technical requirements`, `text`, optional): List technical requirements for the submission to ensure it is properly implemented.
* **Supporting teams** (`Supporting teams`, `text`, optional): List the teams supporting the submission to help with technical issues.
* **Detailed specifications** (`Detailed specifications`, `text`, optional): Provide detailed specifications for the submission to help reviewers understand it better.
* **String format** (`String format`, `text`, required): This field requires the custom string format for the submission.
* **Additional information** (`Additional information`, `text`, optional): Provide any additional information about the submission to give context.
* **Supporting teams 2** (`Supporting teams 2`, `text`, optional): List the teams supporting the submission, if applicable.
* **Technical requirements 2** (`Technical requirements 2`, `text`, optional): List technical requirements for the submission, if required.
* **Organizing requirements 2** (`Organizing requirements 2`, `text`, optional): List the requirements for organizing the submission.
