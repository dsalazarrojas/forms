# Internal Investigation Form - Help Guide
## Purpose
The Internal Investigation Form is used to document and track internal investigations within the company. This form collects information about the incident, the type of investigation, and any findings or next steps.

## How To Complete This Form
1. Ensure you have a valid reason for filling out this form and that it is not a duplicate submission.
2. Start by filling out the form sections in sequential order, from top to bottom.
3. Begin by providing your name and date of birth, if applicable.
4. Select the investigation type that best describes the incident.
5. Describe the details of the incident, including any relevant dates and times.
6. Summarize the findings of the investigation, including any notable observations or results.
7. Outline any next steps or actions that will be taken as a result of the investigation.
8. Finally, indicate whether a specific user is assigned to the investigation and mark the completion date.

## Field-by-Field Explanation
### 1. First Name (<name>, <type>, required/optional)
* First Name is a required field for identifying the individual submitting the form.
### 2. Last Name (<name>, <type>, required/optional)
* Last Name is a required field for identifying the individual submitting the form.
### 3. Date of Event (<name>, <type>, required/optional)
* Date of Event is a required field for tracking the timeline of the incident.
* Enter the date the incident occurred, following the standard date format (YYYY-MM-DD).
### 4. Time of Event (<name>, <type>, required/optional)
* Time of Event is a required field for tracking the timeline of the incident.
* Enter the time the incident occurred, following the standard time format (HH:MM:SS).
### 5. Investigation Type (<name>, <type>, required/optional)
* This field determines the type of investigation being conducted.
* Select 'Yes' if the investigation is a formal investigation, 'No' if it is a casual inquiry.
### 6. Investigation Details (<name>, <type>, required/optional)
* Investigation Details is an optional field for providing additional context or information about the incident.
* Enter a brief description of what happened, including any relevant details or circumstances.
### 7. Findings (<name>, <type>, required/optional)
* Findings is an optional field for summarizing the results of the investigation.
* Enter a brief summary of what was discovered or learned from the investigation.
### 8. Next Steps (<name>, <type>, required/optional)
* Next Steps is an optional field for outlining any actions or next steps resulting from the investigation.
* Enter a brief description of what will be done next or what actions will be taken.
### 9. Assigned User (<name>, <type>, required/optional)
* Assigned User is an optional field for indicating who is responsible for the next steps.
* Select 'Yes' if a user is assigned to the investigation, 'No' if it is not.
### 10. Completed Date (<name>, <type>, required/optional)
* Completed Date is an optional field for tracking when the investigation was completed.
* Enter the date the investigation was finished, following the standard date format (YYYY-MM-DD).

Note: This help guide is based on the provided YAML structure and assumes that some fields may not be relevant or required depending on the specific situation. If you have any questions or concerns, please reach out to the relevant personnel.
