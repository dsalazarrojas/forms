# Quality Incident Closure Request Form - Help Guide
## Purpose
The Quality Incident Closure Request Form is a tool to document the closure of a quality incident, ensuring that all necessary information and steps are captured for future reference and improvement.

## How To Complete This Form
1. Fill out the **Incident Details** field with a brief description of the incident.
2. Provide details about the **Assignee** who was involved in resolving the incident.
3. Select the **Action Status** of the incident (Active or Inactive).
4. Add any additional **Action Details** about the action taken to resolve the incident.
5. Enter your **Comments** about the incident.
6. Optionally, provide **Incident Comments** if you have any additional information to share.
7. Add any **Assignee Comments** if the assignee has any feedback or insights.
8. Optionally, provide **Action Comments** if you have any additional information about the action taken.
9. (Optional) Enter the date and time the action was performed in the **Action Date** and **Action Time** fields.
10. Finally, click the **Submit** button to finalize the form.

## Field-by-Field Explanation
- **Incident Details (1)**: A text field where you should briefy describe the incident.
  * Type: `text`
  * Required: Yes
  * Hint: This field is used to provide a concise description of the incident.
- **Assignee Details (2)**: A text field where you enter details about the assignee.
  * Type: `text`
  * Required: Yes
  * Hint: This field is used to document the assignee's role or involvement in resolving the incident.
- **Action Status (3)**: A dropdown selection to indicate the current status of the action taken.
  * Type: `select_one`
  * Required: No
  * Options: Active, Inactive
  * Hint: Select Active if the incident is still being worked on, or Inactive if it has been resolved.
- **Action Details (4)**: A text field to add any additional details about the action taken.
  * Type: `text`
  * Required: No
  * Hint: Use this field to provide any further insights or notes about the action.
- **Comments (5)**: A text field to add comments about the incident.
  * Type: `text`
  * Required: Yes
  * Hint: Use this field to share your thoughts about the incident.
- **Submit (6)**: A submit button to save the form.
  * Type: `text`
  * Required: No
  * Hint: Click this button to finalize the form.
- **Incident Comments (7)**: A text field for any additional comments about the incident.
  * Type: `text`
  * Required: No
  * Hint: Use this field to provide any additional information about the incident.
- **Assignee Comments (8)**: A text field for any additional comments from the assignee.
  * Type: `text`
  * Required: No
  * Hint: Use this field to capture any feedback or insights from the assignee.
- **Action Comments (9)**: A text field for any additional comments about the action taken.
  * Type: `text`
  * Required: No
  * Hint: Use this field to provide any further information or insights about the action.
- **Action Date (10)**: A field for the date the action was performed.
  * Type: `date`
  * Required: No
  * Hint: If the action was performed on a specific date, enter it here.
- **Action Time (11)**: A field for the time the action was performed.
  * Type: `time`
  * Required: No
  * Hint: If the action was performed at a specific time, enter it here.
- **Action Description (12)**: A text field for the description of the action taken.
  * Type: `text`
  * Required: No
  * Hint: Use this field to document the specific action taken to resolve the incident.
