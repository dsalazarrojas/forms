**Vendor Quality Report Request Form - Help Guide**

## Purpose
The purpose of this form is to gather information about the current status of a vendor's quality, including any issues or incidents that may have arisen in their relationship with the organization.

## How To Complete This Form

1. **Vendor**: Enter the name of the vendor you are reporting on.
2. **Issue Details**: Describe the issue or incident that you are reporting.
3. **Severity**: Select the level of severity of the issue (Yes/No).
4. **Evidence**: Provide any relevant evidence or documentation that supports your report.
5. **Date Reported**: Enter the date the issue was first reported.
6. **Time Reported**: Enter the time the issue was first reported.
7. **Issue Summary**: Briefly summarize the issue or incident.
8. **Issue Description**: Provide a detailed description of the issue or incident.
9. **Impact Assessed**: If applicable, describe the potential impact of the issue or incident.
10. **Action Planned**: If applicable, describe any planned actions to address the issue or incident.
11. **Action Status**: Select the current status of the action planned (Active/Inactive).
12. **Issue Status**: Select the current status of the issue (Active/Inactive).
13. **Close Date**: Enter the date the issue was closed.
14. **Close Time**: Enter the time the issue was closed.
15. **Close Status**: Select the current status of the issue (Active/Inactive).
16. **Issue Category**: Select all applicable categories that describe the issue or incident (Yes/No).
17. **Issue Priority**: Select all applicable priorities that describe the issue or incident (Yes/No).

* **Vendor**: The name of the vendor you are reporting on.
* **Issue Details**: A description of the issue or incident that you are reporting.
* **Severity**: A measure of the level of severity of the issue (e.g. critical, minor).
* **Evidence**: Any relevant documentation or information that supports your report.
* **Date Reported**: The date the issue was first reported.
* **Time Reported**: The time the issue was first reported.
* **Issue Summary**: A brief summary of the issue or incident.
* **Issue Description**: A detailed description of the issue or incident.
* **Impact Assessed**: A description of the potential impact of the issue or incident.
* **Action Planned**: Any planned actions to address the issue or incident.
* **Action Status**: The current status of the action planned (Active/Inactive).
* **Issue Status**: The current status of the issue (Active/Inactive).
* **Close Date**: The date the issue was closed.
* **Close Time**: The time the issue was closed.
* **Close Status**: The current status of the issue (Active/Inactive).
* **Issue Category**: All applicable categories that describe the issue or incident (e.g. technical, administrative).
* **Issue Priority**: All applicable priorities that describe the issue or incident (e.g. high, low).
